01 · Hook

The decision that happens before your UPI "Pay" button finishes animating

Every UPI payment in India, roughly 500 million a day, passes through a fraud model before the money moves. It has about 100 milliseconds. It does not answer "fraud or not". It answers "0.03".

5min

That number is a probability, and the bank decides what to do with it: below 0.02 let it through silently, between 0.02 and 0.3 ask for a second OTP, above 0.3 block and call. Three different actions from one model, decided by thresholds the risk team sets, and can change on a festival weekend when fraud spikes. The model's job is only to produce a calibrated, trustworthy probability. That separation, model gives probability, humans choose the threshold, is the whole design philosophy of classification, and by the end of today you will have built it.

The same machine sits inside a placement cell's shortlist filter (CGPA, aptitude score, internships → "likely to be placed: 0.81"), inside every loan app's approval flow, inside Gmail's spam folder, and, in a slightly bigger costume, inside the last layer of every neural network you will train in Week 3. Logistic regression is the small model you must fully understand because the big ones are built out of it.

02 · Concept

Squeeze the line, draw the boundary, choose the threshold

Three ideas, one demo each. Every slider below is recomputed live in your browser.

18min

Idea 1 · Why not just use linear regression for yes/no?

Try it: label placed = 1, not placed = 0, fit a line to CGPA. The line happily predicts 1.4 for a 9.8 CGPA student and −0.3 for a 5.0 student. Probabilities outside 0–1 are meaningless, and worse, one star student with a huge CGPA drags the whole line and moves the cut-off for everyone. We need the line's output to be squashed into (0, 1), gently, so that far-away points stop pulling. That squasher is the sigmoid: σ(z) = 1 / (1 + e−z). Feed it the linear score z = θ·x, and you get a probability.

🚰

The sigmoid is a tap, not a switch

A light switch is 0 or 1: nothing in between. A water tap goes smoothly from a trickle to full flow. The linear score z is how far you have turned the handle: at z = 0 the tap is exactly half open (p = 0.5); at z = +4 it is 98% open; at z = −4, 2%. Turning the handle further past +6 changes almost nothing, which is exactly why one extreme student no longer drags the whole model. Logistic regression is linear regression with a tap on the output.

Key idea

Gradient descent on log-loss found the same kind of minimum you saw on Day 04, with the same update rule shape θ ← θ − α · (1/m) Xᵀ(ŷ − y). The only thing that changed is that ŷ now passes through the sigmoid. Everything you know about learning rate and convergence carries over untouched.

Idea 2 · The decision boundary is a straight line (in 2-D)

With two features the score is z = θ₀ + θ₁·x₁ + θ₂·x₂. The model says "yes" where z > 0, "no" where z < 0, and the frontier z = 0 is a straight line: the decision boundary. Points far from the line get confident probabilities (near 0 or 1); points near it get ≈ 0.5. Changing the threshold from 0.5 to something else simply slides the line parallel to itself, because p = 0.7 corresponds to z = log(0.7/0.3) ≈ 0.85 instead of z = 0.

Common confusion

"Logistic regression is a linear model, so it can only draw straight boundaries." True in the original features. Feed it polynomial features (Day 05's trick) and the boundary becomes a curve or a circle. It is still called linear because it is linear in θ. The spiral on TensorFlow Playground fails only because we gave it raw x₁, x₂; tick the x₁², x₂², x₁x₂ boxes and watch it succeed.

Idea 3 · The cost function that punishes confident mistakes

MSE would work badly here: with a sigmoid inside, the squared-error surface has flat plateaus where gradient descent stalls. Instead we use log-loss (also called binary cross-entropy). For one example it is −log(p) if the true label is 1 and −log(1 − p) if the label is 0. Read the chart: predicting p = 0.9 for a true "placed" costs 0.1; predicting 0.01 for that same student costs 4.6. Confident and wrong is punished brutally, honest uncertainty (p ≈ 0.5) costs about 0.69 either way. That asymmetry is what pushes the model to be calibrated rather than merely correct.

🏏

DRS review, not the umpire's finger

An umpire's "out / not out" is a hard label. The DRS ball-tracker gives "hitting the stumps: 61%". Log-loss is the scorer that rewards the ball-tracker for being honest about that 61%, and would savage it for saying 99% on a ball that missed. Classification models are trained to be ball-trackers, and the umpire's finger (the threshold) is applied afterwards.

Idea 4 · More than two classes: softmax and one-vs-rest

Sigmoid handles yes/no. For "which of K classes" (cat/dog/cow, or which of 10 digits) we give the model K linear scores z₁…zK and normalise them with softmax: pk = ezk / Σj ezj. The probabilities are positive and sum to 1; the biggest score wins, but the others keep an honest share. Drag the three scores below and watch. The alternative, one-vs-rest (OvR), trains K separate yes/no models ("cat vs everything else", …) and picks the most confident one; simpler, slightly less principled, still common.

Interview answer · "Why is it called regression if it classifies?"

"Because it regresses the log-odds of the positive class as a linear function of the features. The output is a continuous probability; classification only happens when we apply a threshold to it. That is also why you should tune the threshold to the business cost, not always use 0.5."

03 · Deeper

The mechanics: odds, loss, gradient, softmax

Four short formulas. Each one decoded, and one surprising fact: the gradient is the same as linear regression's.

10min

1 · Sigmoid and log-odds

p = σ(z) = 1 / (1 + e−z)  ⟺  log( p / (1 − p) ) = z = θᵀx

p is the predicted probability of class 1, z the linear score, e Euler's number. The right-hand form is the important one: the log-odds (logit) is a straight line in the features. So a coefficient θj = 0.7 means "one unit more of feature j multiplies the odds of the positive class by e0.7 ≈ 2". That sentence is how bankers and doctors read these models, and it is why logistic regression still dominates credit scoring and clinical risk: every weight has a meaning.

2 · Log-loss (binary cross-entropy)

J(θ) = −(1/m) Σi [ yi · log(pi) + (1 − yi) · log(1 − pi) ]

m examples, yi ∈ {0, 1} the true label, pi the model's probability for example i. Only one of the two terms is alive per example (the other is multiplied by zero). It is the negative log-likelihood of the data under the model, so minimising it is the same as maximum likelihood estimation; and unlike MSE-with-sigmoid it is convex, so gradient descent reaches the single global minimum.

3 · The gradient (memorise this one)

∂J/∂θ = (1/m) · Xᵀ (p − y)   so   θ ← θ − α · (1/m) · Xᵀ (σ(Xθ) − y)

Identical in shape to Day 04's linear regression update; the prediction just goes through σ first. The derivative of the sigmoid, σ′(z) = σ(z)(1 − σ(z)), cancels neatly against the log in the loss to give this clean form. In an interview, being able to write this line and say "same as linear regression, sigmoid inside" is a strong signal.

4 · Softmax and the multiclass loss

pk = ezk / Σj=1..K ezj   and   J = −(1/m) Σi log( pi, yi )

K classes, each with its own weight vector θk giving score zk; pi,yi is the probability the model assigned to the correct class of example i. The loss just says "make the correct class's probability large", and it is exactly the loss at the output of every image classifier and every language model (predicting the next token = a softmax over 100k+ classes). In sklearn, LogisticRegression uses this multinomial form by default with the lbfgs solver; OneVsRestClassifier gives you OvR when you want it.

How to say this in an interview

"Logistic regression models the log-odds of the positive class as a linear function of the features and passes it through a sigmoid to get a probability. It is trained by minimising log-loss, which is convex, using gradient-based solvers; the gradient has the same form as linear regression's. I choose the classification threshold from the business cost of false positives versus false negatives, and I regularise with C, where smaller C means stronger regularisation."

04 · Code

From scratch in 15 lines, then sklearn

Full runnable version with plots and the exercise: open Day_06_Logistic_Regression.ipynb in Google Colab.

12min

1 · The model, the loss, the gradient, by hand

import numpy as np

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

def log_loss(y, p, eps=1e-12):
    p = np.clip(p, eps, 1 - eps)                     # never take log(0)
    return -np.mean(y * np.log(p) + (1 - y) * np.log(1 - p))

def fit_logreg(X, y, lr=0.1, epochs=2000):
    Xb = np.c_[np.ones(len(X)), X]                    # prepend the bias column of 1s
    theta = np.zeros(Xb.shape[1])
    for _ in range(epochs):
        p = sigmoid(Xb @ theta)
        grad = Xb.T @ (p - y) / len(y)                # same shape as linear regression's gradient
        theta -= lr * grad
    return theta

theta = fit_logreg(X_train_scaled, y_train)          # scale features first: GD converges much faster
p_test = sigmoid(np.c_[np.ones(len(X_test_scaled)), X_test_scaled] @ theta)
print("log-loss:", log_loss(y_test, p_test), " accuracy:", ((p_test > 0.5) == y_test).mean())
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline

# C is INVERSE regularization strength: C=1.0 default, smaller C = stronger L2 penalty
clf = make_pipeline(StandardScaler(), LogisticRegression(C=1.0, max_iter=1000))
clf.fit(X_train, y_train)

print("accuracy:", clf.score(X_test, y_test))
print("weights :", clf[-1].coef_, "bias:", clf[-1].intercept_)
print("odds ratios:", np.exp(clf[-1].coef_))     # e^θ: how much each (scaled) feature multiplies the odds

2 · Probabilities, not labels

python
proba = clf.predict_proba(X_test)[:, 1]     # column 1 = P(class 1); column 0 = P(class 0)
scores = clf.decision_function(X_test)      # raw z = θᵀx (log-odds); proba == sigmoid(scores)

print(proba[:5].round(3))                      # e.g. [0.91 0.08 0.55 0.73 0.02]
print(clf.predict(X_test)[:5])                # same thing thresholded at 0.5 → [1 0 1 1 0]
print(clf.classes_)                           # [0 1]: tells you which column is which

3 · Tune the threshold to the business cost

python
from sklearn.metrics import confusion_matrix, precision_score, recall_score

for t in [0.3, 0.5, 0.7]:
    y_hat = (proba >= t).astype(int)          # predict() is just this with t = 0.5
    tn, fp, fn, tp = confusion_matrix(y_test, y_hat).ravel()
    print(f"t={t}: TP={tp} FP={fp} FN={fn} TN={tn} "
          f"precision={precision_score(y_test, y_hat):.2f} recall={recall_score(y_test, y_hat):.2f}")

# fraud / medical screening: low threshold (catch everything, accept false alarms)
# loan approval / spam-to-trash: higher threshold (a false positive is expensive)

4 · Multiclass: softmax vs one-vs-rest

python
from sklearn.datasets import load_iris
from sklearn.multiclass import OneVsRestClassifier

Xi, yi = load_iris(return_X_y=True)                       # 3 flower species, 4 features
softmax_clf = LogisticRegression(max_iter=1000).fit(Xi, yi)          # multinomial (softmax) by default with lbfgs
ovr_clf = OneVsRestClassifier(LogisticRegression(max_iter=1000)).fit(Xi, yi)   # 3 separate yes/no models

print(softmax_clf.predict_proba(Xi[:1]).round(3))    # [[0.98 0.02 0.  ]] sums to 1
print(softmax_clf.coef_.shape)                        # (3, 4): one weight row per class
print(ovr_clf.predict_proba(Xi[:1]).round(3))        # OvR normalises 3 independent sigmoids

Gotchas you will hit

ConvergenceWarning: scale your features (put StandardScaler in the pipeline) and/or raise max_iter. Imbalanced classes (2% fraud): accuracy of 98% is worthless; look at recall, and try class_weight="balanced". Day 12 is entirely about this. multi_class= parameter: deprecated since sklearn 1.5; do not pass it, the default is already multinomial.

06 · Career corner

How today shows up in a job

3min
In job descriptions

Risk / Credit Analyst (fintech: Paytm, PhonePe, Navi, Slice; banks: HDFC, ICICI analytics), Data Scientist (churn, conversion, fraud) and ML Engineer postings ask for "classification models", "logistic regression", "probability calibration", "threshold optimisation" and "scorecard development". Logistic regression is the model behind almost every credit scorecard in India because the RBI-regulated world needs weights it can explain.

Real interview questions

  • "Why log-loss instead of MSE for classification?" → MSE through a sigmoid is non-convex with flat regions; log-loss is convex, is the negative log-likelihood, and punishes confident mistakes heavily, which yields calibrated probabilities.
  • "What does a coefficient of 0.7 mean in logistic regression?" → One unit increase in that feature multiplies the odds of the positive class by e0.7 ≈ 2, holding other features fixed.
  • "Your fraud model has 99.8% accuracy. Are you happy?" → No: fraud is 0.2% of data, so predicting "never fraud" scores 99.8%. Look at recall/precision at a chosen threshold, and use class weights or resampling.

07 · Quiz

Three quick checks

3min

A model outputs z = θᵀx = 0 for a student. What is its predicted probability of placement?

σ(0) = 1/(1+e⁰) = 1/2. The decision boundary is exactly the set of points where z = 0, i.e. p = 0.5.

A cancer-screening model must miss as few real cases as possible. Compared to 0.5, its threshold should be…

Lowering the threshold predicts "positive" more often: recall goes up (fewer missed cases), at the cost of more false alarms that a follow-up test can clear.

In sklearn's LogisticRegression, setting C=0.01 instead of the default C=1.0 gives…

C is the inverse of the penalty strength (C = 1/α). Smaller C = bigger penalty = weights shrink toward zero. Easy to get backwards; interviewers know it.

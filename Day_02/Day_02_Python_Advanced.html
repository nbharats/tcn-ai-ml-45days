The story

The 50 GB file

Nikhil's first week at a fintech startup. Task: compute the average transaction size from a 50 GB CSV of UPI payments. He writes rows = f.readlines(), hits Run, and watches his 16 GB laptop freeze, swap, and die. His team lead replaces one line: for row in f:. Same file, same laptop, finishes in 6 minutes with 40 MB of RAM. The file object is a generator: it hands you one line at a time and forgets the previous one.

That single idea, "process a stream instead of loading a mountain", is why PyTorch's DataLoader exists, why LLM training reads terabytes of text on machines with gigabytes of RAM, and why today matters.

02 · Concept

Objects, streams and wrappers

Three mental models. Classes package state and behaviour. Generators pause and resume. Decorators wrap a function in another function. Everything else today (context managers, dataclasses, type hints) is a convenience built on these three.

18min

1. Classes: a blueprint, and the "dunder" hooks Python calls for you

🚂

The IRCTC coach analogy

An IRCTC train coach is a class: the blueprint says "72 berths, 2 toilets, a chart on the door". Coach S4 of the Rajdhani is an instance: the blueprint filled in with real passengers. __init__ is the coach being built and the chart being pasted. len(coach) asks "how many berths?"; coach[23] asks "who is in berth 23?". You never call __len__ yourself; you write len(coach) and Python looks for the hook. That is the entire dunder idea: you implement the hook, Python's built-in syntax calls it. PyTorch's DataLoader is the TTE walking the coach: it calls len() once to know how many berths, then [i] for each one.

__init__(self, ...)Runs when you create an instance. Store the data you were given.ds = ReviewDataset("reviews.csv")
__len__(self)Makes len(obj) work. DataLoader uses it to know how many samples exist.len(ds) → 5000
__getitem__(self, i)Makes obj[i] work. Return ONE sample: (features, label).ds[42] → (tensor, 1)
__repr__(self)What you see when you print it. Make debugging humane.ReviewDataset(n=5000)
__call__(self, x)Makes an instance callable like a function. PyTorch model(x) is this.model(batch) → logits
__enter__ / __exit__Makes with obj: work. Setup, then guaranteed cleanup.with torch.no_grad():
Common confusion

self is not magic. It is simply the instance, passed in as the first argument. ds[3] is sugar for type(ds).__getitem__(ds, 3). When you forget self in a method signature you get "takes 1 positional argument but 2 were given": Python passed the instance and your method had no slot for it.

2. Generators: a function that can pause

🍛

The thali vs the dosa counter

A list is a thali: the kitchen prepares all 12 items, puts them on one plate, and only then hands it over. If the plate is too big for the table (RAM), nothing arrives. A generator is the dosa counter: you ask, one dosa comes off the tawa, you eat it, you ask again. The kitchen remembers where it was (the batter, the heat) between your requests, but only one dosa exists at a time. yield is the moment the cook hands you the dosa and pauses, keeping the tawa hot.

Key idea

Anything with __iter__ and __next__ is an iterator; for loops call them for you. A generator is the easy way to write one: put yield in a function and Python builds the iterator machinery. A generator expression (x*x for x in data) is the one-line version, exactly like a list comprehension with round brackets. Once exhausted, a generator is empty; iterate it twice and the second loop sees nothing. That is the number-one generator bug.

3. Decorators: gift-wrap a function

🎁

The Swiggy packaging analogy

The restaurant cooks the biryani (your function). Swiggy does not change the recipe. It wraps it: a tamper-proof seal (validation), an insulated bag (caching keeps it warm for the next customer), and a "retry delivery if the customer does not answer" policy. The customer still just orders "biryani". A decorator is exactly that: a function that takes your function, returns a wrapped version with extra behaviour, and re-uses the same name. @timer above def train(): is shorthand for train = timer(train).

Why caching earns its keep: the naive recursive Fibonacci recomputes the same sub-problems billions of times. With @functools.lru_cache each fib(k) is computed once and looked up afterwards. Measured on Python 3.11: fib(32) takes 231 ms naively and about 0.02 ms cached, a 10,000× speed-up from one line. In AI code the same decorator caches tokenizer loads, embedding lookups and expensive API calls.

Interview answer

"A decorator is a higher-order function: it takes a function, returns a new function that usually calls the original with something added (timing, logging, caching, retries, auth), and the @ syntax rebinds the original name to the wrapper. Use functools.wraps so the wrapper keeps the original's name and docstring."

03 · Deeper

How each one actually works

Ten minutes of mechanics, so that none of this is magic when you read library code.

10min

Inheritance and super(): extend, don't copy

A child class gets everything the parent has, and can override pieces. class ImageDataset(Dataset): inherits the base machinery and only fills in __len__ and __getitem__. Inside the child's __init__, super().__init__() runs the parent's setup first; forgetting it in PyTorch's nn.Module is a classic bug (the parameters are never registered). Prefer composition ("has a") over deep inheritance ("is a"): a Trainer that has a model and an optimizer is easier to test than a Trainer(Model, Optimizer) that is both.

The decorator, without the sugar

python
import time, functools

def timer(fn):                                # 1. takes a function
    @functools.wraps(fn)                          # keeps fn.__name__ and docstring
    def wrapper(*args, **kwargs):               # 2. accepts ANY arguments
        t0 = time.perf_counter()
        result = fn(*args, **kwargs)              # 3. calls the original, passing them through
        print(f"{fn.__name__} took {time.perf_counter() - t0:.3f}s")
        return result                             # 4. returns whatever the original returned
    return wrapper                                # 5. hands back the wrapped function

@timer                                            # same as: train = timer(train)
def train(epochs=3): ...

Decode *args, **kwargs: *args collects any positional arguments into a tuple; **kwargs collects any keyword arguments into a dict. In the call fn(*args, **kwargs) the same stars unpack them back out. This is why one wrapper can wrap any function regardless of its signature. A decorator that takes parameters, like @retry(times=3), is one more layer: a function that returns a decorator.

Context managers: setup, do the work, cleanup even on failure

with X as y: calls X.__enter__() (its return value becomes y), runs your block, then calls X.__exit__(exc_type, exc, tb) no matter how the block ended, even via an exception. That guarantee is why with open() never leaks file handles, why with torch.no_grad(): reliably turns gradients back on afterwards, and why database transactions commit or roll back correctly. The shortcut: decorate a generator with @contextlib.contextmanager, put the setup before yield and the cleanup after.

Type hints do not change runtime behaviour; Python ignores them when running. They exist for humans and tools. Modern syntax (3.10+): list[int] not List[int], int | None not Optional[int]. A dataclass with frozen=True is hashable, so it can be used as an lru_cache key or a dict key.

How to say this in an interview

"I write classes when data and behaviour belong together, and I implement dunder methods so the object plugs into Python's syntax: __len__ and __getitem__ make it a Dataset, __call__ makes it a model. I use generators to stream data that does not fit in memory, decorators to add cross-cutting behaviour like timing, retries and caching without touching the function body, and dataclasses with type hints for configs so they are self-documenting and tool-checkable."

Snippet 1 — a Dataset class (this is the PyTorch shape, minus torch)

python
from dataclasses import dataclass

@dataclass(frozen=True)
class Sample:
    text: str
    label: int                                   # 1 = positive review, 0 = negative

class ReviewDataset:
    def __init__(self, rows: list[Sample], transform=None):
        self.rows = rows
        self.transform = transform               # optional function applied per item

    def __len__(self) -> int:
        return len(self.rows)

    def __getitem__(self, i: int) -> tuple[str, int]:
        s = self.rows[i]
        text = self.transform(s.text) if self.transform else s.text
        return text, s.label

    def __repr__(self):
        return f"ReviewDataset(n={len(self)})"

ds = ReviewDataset(rows, transform=str.lower)
print(ds, len(ds), ds[0])                        # ReviewDataset(n=6) 6 ('the biryani was superb', 1)
for text, label in ds: ...                       # __getitem__ + IndexError makes it iterable too

On Day 21 the only changes are class ReviewDataset(torch.utils.data.Dataset) and returning tensors instead of strings. The DataLoader will call exactly these two methods.

Snippet 2 — a generator pipeline that streams a big file

python
def read_lines(path):                        # stage 1: one line at a time from disk
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.rstrip("\n")

def parse(lines):                             # stage 2: string -> (amount, city)
    for line in lines:
        amt, city = line.split(",")
        yield float(amt), city

def batched(items, size):                     # stage 3: group into batches
    batch = []
    for it in items:
        batch.append(it)
        if len(batch) == size:
            yield batch; batch = []
    if batch: yield batch                     # last partial batch

pipeline = batched(parse(read_lines("upi.csv")), size=32)   # NOTHING has run yet
for batch in pipeline:                        # now rows flow through, 32 at a time
    total += sum(a for a, _ in batch)

Each stage pulls from the one before it, so at any moment at most one batch of parsed rows is alive in memory. Files of any size run in constant RAM. Python 3.12 ships itertools.batched that does stage 3 for you.

Snippet 3 — three decorators every ML repo ends up with

python
import time, functools

def timer(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        t0 = time.perf_counter()
        try:
            return fn(*args, **kwargs)
        finally:                                   # prints even if fn raises
            print(f"⏱ {fn.__name__}: {time.perf_counter()-t0:.3f}s")
    return wrapper

@timer
def train_epoch(n):
    return sum(i*i for i in range(n))
python · a decorator WITH arguments = one extra layer
def retry(times=3, delay=0.5, exceptions=(Exception,)):
    def decorator(fn):                       # this is the real decorator
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return fn(*args, **kwargs)
                except exceptions as e:
                    if attempt == times: raise    # out of tries: re-raise
                    print(f"attempt {attempt} failed ({e}); retrying in {delay}s")
                    time.sleep(delay)
        return wrapper
    return decorator

@retry(times=3, delay=0.2, exceptions=(ConnectionError,))
def call_llm_api(prompt): ...              # flaky network: exactly where retry belongs
python · memoisation from the standard library
from functools import lru_cache

@lru_cache(maxsize=None)                     # cache every distinct argument
def fib(n):
    return n if n < 2 else fib(n-1) + fib(n-2)

fib(80)                                      # instant; naive version would take centuries
print(fib.cache_info())                      # CacheInfo(hits=78, misses=81, ...)

@lru_cache(maxsize=4)
def load_tokenizer(name: str): ...           # heavy load happens once per model name

Snippet 4 — a context manager for timing a block, and a typed config

python
from contextlib import contextmanager
from dataclasses import dataclass, field

@contextmanager
def timed(label: str):
    t0 = time.perf_counter()                     # __enter__ part
    try:
        yield                                    # the with-block runs here
    finally:
        print(f"{label}: {time.perf_counter()-t0:.3f}s")   # __exit__ part, always

@dataclass
class TrainConfig:
    lr: float = 1e-3
    epochs: int = 5
    batch_size: int = 32
    tags: list[str] = field(default_factory=list)   # NEVER tags: list = []  (shared default!)

cfg = TrainConfig(lr=3e-4, tags=["baseline"])
with timed("epoch 1"):
    run_epoch(cfg)                               # TrainConfig(lr=0.0003, epochs=5, batch_size=32, tags=['baseline'])
Key idea

Look at what you now have: a Dataset that PyTorch can consume, a streaming pipeline that handles any file size, decorators for timing / retrying / caching, a context manager for scoped setup and cleanup, and a typed config. That is the skeleton of every training repo you will see, and you built all of it with plain Python.

06 · Career corner

"Explain decorators" is a filter question

3min
In job descriptions

ML Engineer, AI/Backend Engineer (Python), Data Engineer. The JD line reads "Strong Python including OOP, generators and decorators; experience writing clean, testable code". In a technical screen this shows up as "write a decorator that logs the arguments" or "read this class and tell me what len() returns". These are filter questions: they separate "can write scripts" from "can maintain a codebase". After today you are on the right side of the filter.

Interview questions you can now answer

  • "What is a generator and when would you use one?" — A function that uses yield to return values lazily, one at a time, keeping its state between calls. Use it for streaming data larger than memory, infinite sequences, and pipelines where each stage pulls from the previous.
  • "What does a decorator do, and why functools.wraps?" — It replaces a function with a wrapper that adds behaviour around the original call. wraps copies the original's __name__/__doc__ so logging, debugging and documentation tools still see the real function.
  • "Difference between __str__ and __repr__?" — __repr__ is for developers (unambiguous, ideally re-creatable), __str__ for users (readable). print uses __str__ and falls back to __repr__.

Job-hunt action for today

Create a file ml_utils.py in your ai-ml-45days repo with your @timer, @retry and timed() context manager, each with a docstring and type hints. Commit with the message "add reusable ML utilities". You will import this file on Day 21 and Day 43, and "I maintain a small utilities library I reuse across projects" is a sentence that lands well in interviews.

07 · Quiz

Three quick checks

3min

g = (x*x for x in range(3)); print(list(g)); print(list(g)) prints?

A generator is exhausted after one pass. The second list(g) finds nothing left. If you need two passes, build a list or recreate the generator.

Which two methods must a class implement to be usable by PyTorch's map-style DataLoader?

DataLoader asks "how many samples?" (len) and "give me sample i" ([i]). Everything else is optional.

@timer written above def train(): is equivalent to…

The decorator receives the function object (not its result) and its return value is rebound to the name train. Note the absence of parentheses after train: it is not called yet.

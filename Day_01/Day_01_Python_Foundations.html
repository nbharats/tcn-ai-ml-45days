02 · Concept

Names, objects, and the flow of data

Four ideas carry 80% of Python: everything is an object, a variable is a name stuck on an object, data lives in four containers, and functions are the pipes that move it.

17min

1. Variables are stickers, not boxes

In C you learned "a variable is a box that holds a value". Python is different, and the difference causes half of all beginner bugs in AI code. In Python the object (a list, a number, a model) lives somewhere in memory, and a variable is just a name sticker you slap on it. b = a does not copy the box; it puts a second sticker on the same object.

🍱

The tiffin analogy

One steel tiffin box on the table. You write "Rahul" on a sticky note and stick it on. Then you write "Lunch" on another note and stick that on too. Two names, one box. If Rahul opens it and eats a roti, "Lunch" also has one roti less; it is the same box. That is b = a for a list. But if you instead pack a new tiffin with the same food (c = a[:] or a.copy()), now there are two boxes and eating from one does not touch the other.

Common confusion

"I passed my list into a function and the function changed it. Python is pass-by-reference?" Not quite. Python is pass-by-object (also called pass-by-assignment): the function gets another sticker on the same object. If the object is mutable (list, dict, set, NumPy array, PyTorch tensor) the function can change it in place. If it is immutable (int, float, str, tuple) it cannot; any "change" creates a new object. This is exactly why df.dropna() in Pandas returns a new frame while df.dropna(inplace=True) does not.

2. The four containers you will meet in every AI script

list [ ]Ordered, mutable, allows duplicates. The default "bag of things".losses = [0.9, 0.7, 0.5]
tuple ( )Ordered, immutable. Use for things that should not change: shapes, coordinates, function returns.shape = (28, 28, 3)
dict { k: v }Key → value lookup. Configs, JSON, model hyperparameters, word counts.cfg = {"lr": 0.01, "epochs": 5}
set { }Unordered, unique items. "Which skills appear in ANY job?" is a set union.{"python","sql"} & jd_skills

A rule of thumb that survives all the way to PyTorch: if the order matters and it will grow, list. If it is a fixed record, tuple. If you look things up by name, dict. If you only care about membership, set. An image batch in PyTorch has a shape that is a tuple (fixed record). Training losses go in a list (grows every epoch). Hyperparameters go in a dict (looked up by name). Vocabulary is a set (membership).

3. Control flow is the traffic police

A program without if and for is a straight road. Control flow lets data take different routes. Python has no braces: indentation is the syntax. Four spaces, always. A training loop in PyTorch is literally a for epoch in range(N): containing a for batch in loader:, so learn to read nested loops like a story.

4. Functions are pipes, and they are also objects

🫖

The chai stall analogy

A function is a chai-wala's recipe: fixed steps, some inputs with defaults (sugar=2), and an output. You do not re-explain the recipe every time; you just say make_chai(sugar=0). The AI-code twist: in Python the recipe itself is a thing you can hand to someone. You can pass make_chai to a scheduler that calls it every morning. Tomorrow's decorators are exactly that: a function that takes your function, wraps it (adds a timer, a retry, a cache) and hands it back.

Signature you will see daily

Defaults, keywords, docstring

python
def train(model, data, epochs=5, lr=0.01):
    """Train model on data. Returns list of losses."""
    losses = []
    for epoch in range(epochs):
        loss = step(model, data, lr)
        losses.append(loss)
    return losses

train(m, d)                  # defaults used
train(m, d, lr=0.1)          # keyword arg: readable!
Why this matters for AI code

Every library API is a function with keyword defaults

LinearRegression(fit_intercept=True), torch.optim.Adam(params, lr=1e-3), pd.read_csv(path, sep=","). When you read documentation you are reading a function signature. When you see lr=1e-3 you should instantly parse: "keyword argument, float in scientific notation, 0.001".

A function that returns a value ends the story; a function that mutates its input (like optimizer.step() updating the model in place) is the sticker idea again. Both patterns are everywhere.

Why not just write the loop? (numbers)

The same job: sum of squares of the even numbers below one million. Four ways to write it, measured on Python 3.11 on a laptop. The loop, the comprehension and the generator are all "Python speed", within 15% of each other; the difference is readability, not performance. NumPy is a different animal because the loop runs in C. That is Day 03's whole point: write the expression, not the loop.

Key idea

Learn comprehensions for clarity (one line says "what", not "how"), and learn NumPy/Pandas for speed. A senior engineer's code has almost no bare for loops over numbers.

Interview answer

"Why is Python the language of AI?" — Python is glue: readable, dynamically typed and interactive, so researchers iterate fast, while the heavy numerical work happens in C/C++/CUDA underneath libraries like NumPy and PyTorch. You get the productivity of a scripting language with near-native speed where it counts.

03 · Deeper

The five idioms that make AI code look like AI code

f-strings, comprehensions, lambdas, try/except and with open. Once you can read these five, most training scripts stop looking cryptic.

Decoding a comprehension

Read it as three parts, in this order: [ expression for item in source if condition ]. The source is where items come from (a list, a file, a range). The item is the name given to each one. The condition is a gate; items that fail it are skipped. The expression is what actually gets stored. It is exactly the for-loop you already know, folded into one line, and it runs slightly faster because Python does not have to look up .append a million times.

Decoding an f-string format spec

f"{loss:8.4f}" reads as: take loss, format as a fixed-point float (f) with 4 digits after the decimal (.4) padded to a total width of 8 characters (8). f"{acc:.1%}" multiplies by 100 and adds a percent sign. f"{n:,}" adds thousands separators (1,000,000). f"{name!r}" shows the value with quotes for debugging. These four cover every log line you will ever write.

Error handling: the difference between a script and a tool

A script crashes at row 3,417 of a CSV because the salary column says "Not disclosed". A tool catches that, counts it, and keeps going. The shape is always the same: try the risky thing, except the specific error you expect (ValueError, FileNotFoundError, KeyError), optionally else on success, and finally for cleanup that must happen regardless. Never write a bare except: in production; it also swallows KeyboardInterrupt and hides real bugs.

Common confusion

import vs pip install. pip install pandas downloads the package to your machine once (a one-time purchase). import pandas as pd loads it into the current program (taking it out of the cupboard). In Colab, most packages are pre-installed; you only !pip install the ones that are missing. A module is any .py file; a package is a folder of modules with an __init__.py. When you write from utils import clean, Python looks for utils.py next to your script or on the path.

How to say this in an interview

"Python's core strengths for data work are readability and expressiveness: comprehensions and f-strings let you say what you want in one line, everything is an object so functions can be passed around, and exceptions let a pipeline degrade gracefully on bad rows instead of crashing. Mutability is the main thing to watch: lists and dicts are shared by reference, so I copy explicitly when I need isolation."

04 · Code

Build: the salary-vs-skills analyzer (pure Python)

A CSV of job postings: title, company, city, salary in LPA, and a skills column. Which skill is worth the most? No pandas yet; we do it with the tools from today. Full runnable version: open Day_01_Python_Foundations.ipynb in Google Colab.

13min

Snippet 1 — read the file, guard against bad rows

python
import csv

rows, skipped = [], 0
with open("jobs.csv", newline="", encoding="utf-8") as f:
    for r in csv.DictReader(f):            # each row is a dict: {"title": ..., "salary_lpa": ...}
        try:
            r["salary_lpa"] = float(r["salary_lpa"])   # "Not disclosed" → ValueError
        except ValueError:
            skipped += 1
            continue                              # skip this row, keep going
        r["skills"] = {s.strip().lower() for s in r["skills"].split(";")}  # set comprehension
        rows.append(r)

print(f"loaded {len(rows):,} rows, skipped {skipped}")

Snippet 2 — count, filter, and sort with comprehensions and lambda

python
# every distinct skill across all postings = set union
all_skills = set().union(*[r["skills"] for r in rows])

# dict comprehension: skill -> average salary of jobs that ask for it
avg_by_skill = {
    s: sum(r["salary_lpa"] for r in rows if s in r["skills"])
       / sum(1 for r in rows if s in r["skills"])
    for s in all_skills
}

# sort dict items by value (a tuple (skill, avg)), highest first
top = sorted(avg_by_skill.items(), key=lambda kv: kv[1], reverse=True)
for skill, avg in top[:5]:
    print(f"{skill:<12} {avg:6.1f} LPA")      # <12 = left-align in 12 chars

Snippet 3 — the same job three ways

python · how a beginner writes it
counts = {}
for r in rows:
    for s in r["skills"]:
        if s in counts:
            counts[s] += 1
        else:
            counts[s] = 1
python · one comprehension + dict.get
counts = {}
for s in [s for r in rows for s in r["skills"]]:   # nested comprehension = flatten
    counts[s] = counts.get(s, 0) + 1                 # .get(key, default) avoids the if/else
python · how a senior engineer writes it
from collections import Counter
counts = Counter(s for r in rows for s in r["skills"])
print(counts.most_common(5))     # [('python', 412), ('sql', 300), ...]

python · jobs_tool.py

Every serious repo you clone, from scikit-learn to Ultralytics, is built from files that look like this.

Interview questions you can now answer

  • "List vs tuple?" — Both ordered; list is mutable and grows, tuple is immutable and hashable (usable as a dict key). Use tuples for fixed records like shapes.
  • "Is Python pass-by-value or pass-by-reference?" — Neither; pass-by-object. The callee gets a reference to the same object, so mutable objects can be changed in place, immutable ones cannot.
  • "What is wrong with def f(x, acc=[])?" — The default list is created once at definition time and shared across calls, so it keeps growing. Use acc=None and create the list inside.

07 · Quiz

Three quick checks

3min

a = [1, 2]; b = a; b.append(3); print(a) prints?

b = a adds a second sticker to the same list object. Appending through either name changes the one list. To get an independent copy use a.copy() or a[:].

What does [w.upper() for w in words if len(w) > 3] produce?

Read it as: expression w.upper(), for each w in words, only if the condition holds. The if filters, the expression transforms.

Which is the correct way to catch a bad number conversion?

Catch the specific error you expect. A bare except: also swallows Ctrl-C and typos; pass on Exception hides every bug silently.
